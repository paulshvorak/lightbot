# lightbot (СвітлоБот)

Telegram-бот для моніторингу графіків відключення світла (Волиньобленерго). Бот розпізнає зображення графіка з сайту обленерго (OpenCV), підписує користувачів на одну або кілька черг/підчерг і надсилає пуш-повідомлення при зміні графіка.

## Команди

### Для всіх користувачів
| Команда | Опис |
|---|---|
| `/start` | Почати роботу з ботом / відкрити меню |
| `/id` | Показати свій `user_id` і `chat_id` |

Основна взаємодія відбувається не через команди, а через кнопки меню (див. нижче).

### Для адміністраторів (`ADMIN_IDS` у `lightbot/config.py`)
| Команда | Опис |
|---|---|
| `/say <chat_id> <текст>` | Надіслати повідомлення конкретному користувачу (або reply на повідомлення + `/say <chat_id>`) |
| `/broadcast <текст>` | Розіслати повідомлення всім користувачам з хоча б однією підпискою (або reply на повідомлення + `/broadcast`) |
| `/last` | Показати останнього нового користувача (chat_id, username, дати) |
| `/users` | Таблиця останніх 200 активних користувачів (chat_id, username, остання активність) |
| `/stats` | Загальна кількість користувачів + приріст нових по днях за останні 14 днів |

## Функціонал

### Підписка на черги
Один користувач (`chat_id`) може стежити за **кількома чергами одночасно** (наприклад, дім + робота), максимум **3** (`MAX_SUBSCRIPTIONS`). Формат позначення — `Черга.Підчерга` (наприклад `5.2`). Керування через кнопку **⚙️ Встановити/змінити чергу**:
- заголовок списку одразу показує ліміт — «Твої черги (2/3):»
- список уже доданих пар, для кожної — **✏️ назва** (перейменувати) і **❌** (видалити)
- **✏️ Перейменувати** — довільний текст до 24 символів стає відображуваною назвою підписки замість «Черга X.Y» (написати `-` — прибрати назву)
- **➕ Додати чергу** → сітка всіх 12 варіантів (1.1–6.2) на одному екрані, вже додані позначені ✅; після вибору одразу показується поточний графік для щойно доданої пари
- після додавання — **➕ Додати ще чергу** або **✅ Готово**
- якщо вже є 3 черги — решта варіантів у сітці позначені 🔒, додати нову можна лише видаливши одну з наявних

### Перегляд графіка
**🔍 Чи є світло зараз?** — одне повідомлення на всі підписані черги одразу, блок на кожну:
```
📍 Дім
💡 Зараз є світло
❌ 17:30–21:00

📍 Робота
❌ Немає світла (ще 25 хв)
❌ 11:00–14:00
```
Назва черги — жирним (HTML `parse_mode`). Кожен проміжок без світла — окремий рядок, без групування по частинах доби. Показуються лише майбутні відключення (минулі приховуються).

Кнопка має кулдаун (30с на чат) від спаму повторними натисканнями.

### Автоматичні пуші (`lightbot/scheduler.py`)
Фонові задачі (APScheduler) незалежно від того, чи користувач відкриває бота:
- **Кожні 5 хв** — перевірка, чи змінився графік "на сьогодні" для підписаних черг; якщо змінилось кілька черг одного чату в межах одного циклу — **один** пуш на весь чат (блок на кожну чергу), а не окреме повідомлення на кожну
- **Кожні 5 хв, з 18:00 до 23:00** — те саме для графіка "на завтра" (перша публікація і подальші оновлення теж згруповані по чату); ручної кнопки для "завтра" немає — лише автопуш
- **О 00:30** — тихий "baseline": зберігає поточний стан дня без розсилки (щоб з 06:00 було з чим порівнювати)
- **Тихі години 00:00–06:00** — автоматичні пуші не шлються (ручна кнопка "Зараз" працює як завжди)

Якщо надсилання провалилось з `Forbidden` (користувач заблокував бота) — запис про користувача видаляється з бази автоматично.

Запити до API графіків і розпізнавання зображення виконуються в окремому треді (`asyncio.to_thread`) — не блокують event loop бота під час очікування відповіді обленерго.

### Fallback для старих клавіатур
`on_restart` (кнопка «🔄 Рестарт») і `on_unknown_callback` (ловить будь-яку необроблену кнопку) — тимчасова підтримка повідомлень зі старою клавіатурою, що лишились у чатах користувачів з-перед переходу на мультичергову модель.

### Дані
SQLite (`DB_PATH`, WAL-режим), дві таблиці:
- `users` — chat_id, username, created_at, last_seen_at (профіль/активність)
- `subscriptions` — `(chat_id, queue, subqueue)` як складений ключ, `label` (назва від юзера), плюс окрема пам'ять `today_*`/`tomorrow_*` на кожну пару (для анти-дублів пушів: порівняння з попереднім станом, а не повторна розсилка того самого)

Підключення до SQLite (`db_connect`) завжди закривають з'єднання при виході з `with`-блоку (кастомний підклас `Connection`) — щоб не накопичувались відкриті файлові дескриптори при частих запитах.

## Структура проєкту
```
lightbot/
  app.py            — точка входу, реєстрація хендлерів
  config.py         — конфіг, env-змінні, HTTP-сесія з retry
  db.py             — SQLite-доступ (dataclasses Subscription/UserRecord)
  image.py          — завантаження зображення графіка (з кешем)
  grid.py           — розпізнавання зображення графіка (OpenCV) → матриця 12×48
  formatting.py     — побудова тексту повідомлень, розрахунок інтервалів
  scheduler.py      — фонові задачі пушів
  keyboards.py      — inline-клавіатури
  errors.py         — глобальний обробник помилок
  handlers/
    user.py         — користувацькі команди та кнопки
    admin.py        — адмінські команди
bot.py              — запускає lightbot.app.main()
```

## Запуск
```bash
export BOT_TOKEN="<токен з @BotFather>"
python3 bot.py
```
Опційно: `DB_PATH` (шлях до SQLite-файлу, за замовчуванням `users.db` у робочій директорії), `TEST_MODE=1` для локального тестування без звернення до сайту обленерго.
